## 構成


## 2つの層

**カテゴリ直下は「現在地の地図」です。**
`README.md`（論点マップ）、`baseline.md`（出発点）、`refs.md`（文献リスト）の3つを置き、常に最新の状態に保ちます。

**`studies/` は「個別の検討」です。**
1件ずつ日付つきで積み上げていきます。書き終えた検討は原則として書き換えず、結論は論点マップのほうに反映します。

ソフトウェア開発の ADR（Architecture Decision Records）と同じ考え方です。

## 検討フォルダの名前

```
YYYY-MM-DD_english-slug_日本語の短い名前
```

| 部分 | 中身 |
|---|---|
| `YYYY-MM-DD` | 着手した日 |
| `english-slug` | 英小文字。単語はハイフンでつなぐ。2〜4語くらい |
| `日本語の短い名前` | 内容が一目で分かるラベル。15文字くらいまで |

- 3つの部分はアンダースコア `_` で区切ります。**各部分の中ではアンダースコアを使いません。**
- 英語を先に置くのは、ターミナルで IME を切り替えずに Tab 補完するためです。
- 正式なタイトルは README 先頭のメタデータの `title` に書きます。
- **フォルダ名は一度作ったら変えません。** 言い回しを直したいときは `title` を直します。
- 使わないもの: スペース（半角・全角とも）、記号 `/ \ : * ? " < > | # %`、全角英数字。

例:

```
2026-10-08_memoryforge_MemoryForge論文の解釈
2026-10-20_recall-bias_想起バイアスの記述
2026-11-02_forgetting-models_忘却モデルの比較
```

## 検討のメタデータ

各検討の `README.md` の先頭に YAML で書きます。GitHub では表として表示されます。

```yaml
---
title: MemoryForge論文の解釈検討
type: paper
status: done
issues: [MEM-01, MEM-04, MEM-05, MEM-06]
papers: [arXiv:2608.00007]
started: 2026-10-08
updated: 2026-10-08
superseded_by:
---
```

| 項目 | 中身 |
|---|---|
| `title` | 正式なタイトル（日本語） |
| `type` | `paper`＝論文の精読・解釈 / `design`＝設計の検討 / `experiment`＝実験 / `survey`＝調査・比較 |
| `status` | `active`＝検討中 / `done`＝完了 / `adopted`＝スキーマなどに反映済み / `rejected`＝不採用 / `superseded`＝後の検討に置き換え |
| `issues` | 関係する論点のID |
| `papers` | 扱った論文（`arXiv:XXXX.XXXXX` や DOI） |
| `started` / `updated` | 着手日 / 最終更新日 |
| `superseded_by` | `superseded` のときだけ、後継の検討フォルダ名を書く |

---

## 論点ID

- 形式は `<論点コード>-<2桁の番号>` です（例: `MEM-04`）。論点コードはカテゴリごとに英大文字3文字で決め、上のカテゴリ一覧に書きます。
- **章番号ではなくIDで参照します。** 論点マップの章を並べ替えても、IDは変えません。
- 論点をなくしたときは欠番にし、番号を再利用しません。

## 情報の流れ

```
検討（studies/）
  → 論点マップの「結論」と「決定事項ログ」に反映（根拠として検討へのリンクを付ける）
    → schema/ や eval/ に実装
      → 検討の status を adopted にし、反映したコミットを記録
```

## 運用ルール

- **1件1フォルダにします。** 中身が README だけでも、最初からフォルダで作ります。後でデータや図を足してもリンクが壊れません。
- **論点別や種別でフォルダを分けません。** 1つの検討が複数の論点にまたがることがあるからです。関係する論点と種別はメタデータで持ちます。
- **複数のカテゴリにまたがる検討**は、主なカテゴリに1つだけ置き、他のカテゴリの論点マップの「関連する他カテゴリの検討」からリンクします。コピーはしません。
- **論文**は、カテゴリの `refs.md` に載せます。精読したものには ★ を付け、精読メモを書いた検討へリンクします。
- 論点マップの中で、1つの論点の議論が1画面を超えそうになったら、`type: design` の検討として切り出し、論点マップには結論とリンクだけを残します。
- **不採用（`rejected`）や置き換え（`superseded`）になった検討も消しません。** 同じ議論を繰り返さないための記録です。
- 論文の PDF は置きません（`.gitignore` 対象）。リンクで参照します。
- `research/` も公開されます。公開できない内容は書かないでください。

## 手順

### 新しい検討を始める

1. `_templates/study/` をカテゴリの `studies/` にコピーし、命名規則に従ってフォルダ名を付ける。
2. README 先頭のメタデータを埋める。
3. カテゴリの論点マップの「検討一覧」に1行追加し、関係する論点の「関連する検討」にリンクを足す。
4. リポジトリ直下の `filelist.html` を更新する。

### 新しいカテゴリを作る

1. `_templates/category/` を `research/<英語のカテゴリ名>/` としてコピーし、`studies/` フォルダを作る。
2. 論点コード（英大文字3文字）を決める。
3. このファイルのカテゴリ一覧に1行追加する。
4. `filelist.html` を更新する。

> 検討一覧やカテゴリ一覧の表は、当面は手で更新します。検討が増えてきたら、メタデータから表を自動生成するスクリプトを作る予定です。
