## 凡例

各論点は次の4ブロックで構成する。

- **現状** — 今のGDLがどうなっているか（事実）
- **論点** — 何を決める必要があるか
- **結論** — 議論の結果決まったこと。次の3段階で区別する
  - `■ 確定` — 設計方針として決まった。あとは実装するだけ
  - `▲ 方針確定` — 方向は決まったが、検証や前段の実験を通さないと実装に進めない
  - `⏳ 未確定` — まだ議論していない
- **関連する検討** — この論点を扱った検討へのリンク

論点は ID（`MEM-01` など）で参照する。章を並べ替えても ID は変えない。

## MEM-01 なぜ記憶を検討するのか

### 現状

GDLの11セクションのうち `episodes` のみが三層構造を持たず、`storage_type: "RAG"` と空の `sources` テンプレートを持つだけの状態。記憶は事実上、設計されないまま外部に追い出されている。

### 論点

- GDLが記述する「人格」に、記憶はどこまで必要か
- 記憶なしで再現できるもの／できないものの境界はどこか

### 結論

■ **確定** — 記憶はGDLに必要。ただし「目標人格から逆算して記憶を合成し、それで人格を発現させる」路線は採らない。

GDLは実在の個人を対象とし、記憶には真偽がある。没後継承の用途では、本人が経験していないことを本人の記憶として語るAIは継承ではなく捏造になる。MemoryForge と GDL は出自（実在か合成か）の点で別の問題を解いており、競合関係ではない。

記憶なしで再現できるものの境界については、口調・言い回し（Linguistic Habits）がラベル記述だけでは不足する可能性が高いことが判明した。検証は MEM-06 に項目を立てた。

合成が許容される例外を2つ認める。

- GDL_eval の質問設計・採点ロジック検証用のテストデータ生成
- 本人から取得できていない領域の記憶を合成して見せ、「これは違う」と否定させることで情報を引き出す**取得手法**としての転用（記録には残さない）

### 関連する検討

- [MemoryForge論文の解釈](studies/2026-10-08_memoryforge_MemoryForge論文の解釈/) — §4（記述の出自）、§9（採らない判断）

## MEM-03 想起バイアス — 記憶の「効き方」の記述

### 現状

記述項目なし。想起は外部RAGの汎用エンジンに委ねられており、本人固有性は入っていない。

### 論点

- どんな軸で想起の偏りを記述するか
- 三層（Lv1/Lv2/Lv3）にどう割り付けるか
- 本人の自己申告で取得可能か、テキスト分析で推定するしかないか
- 実装時、RAGの検索・再ランキングにどう反映させるか

### 結論

▲ **方針確定**（記述項目の設計は再現実験待ち） — 想起バイアスの個人化は先行研究の空き地であることが確認された。GDL独自の枠として維持する。

MemoryForge も検索は類似度ベースの top-k であり、記憶の**内容**は個人化したが記憶の**効き方**は万人共通のまま残している。記憶の内容の個人化は MemoryForge、減衰・忘却の生物学的模倣は FSFM / ACT-R 系が押さえているが、想起の偏り自体を個人ごとに記述する研究は見つかっていない。

ただし記述項目の設計より先に小さな再現実験を置く。[2605.25680](https://arxiv.org/abs/2605.25680) が、プロンプトでは人間的な忘却を誘導できず、作業記憶を制限して量的劣化を作れても誤りの「種類」は人間と異なることを示しているため。

置き場所は MEM-05 で導入する `_retrieval` の下に `personal_bias` として置く案が有力。

> ⚠️ 再現実験が「プロンプト指定では動かない」と出た場合、GDLが持つべきは自然言語の記述ではなく数値パラメータになる。これはGDLの可読性とポータビリティという価値に関わるので、その時点で立ち止まって方針を決め直す。

## MEM-04 定型エピソード — 自己物語の部品

### 現状

記述枠なし。`preferences.Lv3.sensory_memories` が近いが役割が異なる。

### 論点

- 本数の上限をどう決めるか
- 1本あたりのスキーマ（出来事／解釈／繰り返し語られる文脈／人格のどの側面を説明するか）
- `episodes`（RAG側）と名前空間をどう分けるか
- 取得方法（GDL_questions.json への設問追加が必要か）

### 結論

■ **確定**（スキーマ実装は未着手）

- **本数で絞るのではなく解像度で三層に分ける。** `life_periods`（L: 人生の時期の要約）／ `general_events`（G: 反復的・典型的な出来事）／ `defining_episodes`（E: 特定の一場面）
- **E層には内的思考を含める。** 出来事の記述だけでは、同じ出来事から何を感じ取ったかが落ちる。そこが個性の所在に近い
- **高解像度の配分先は直近ではなく人格形成期とする。** MemoryForge は効率のため直近5年に集中させているが、継承を目的とするなら配分の基準は逆になる
- **3歳以前は対象外とする。** 幼児期記憶欠如が根拠。本人が語る幼児期の話は本人の記憶ではなく家族から伝えられた物語として別扱いする
- **語り口の鋳型 `narrative_style` を必須項目とする。** LLMは元の話に無くても贖罪型（苦難→成長→解決）の枠を押しつけるため、内容だけ正確に入れても語り直しで汚染される
- **名前空間は `episodes`（RAGポインタ）と分け、新設は `autobiography` とする**
- **MemoryForge にない要素を2つ持たせる。** `explains`（このエピソードが人格のどの側面を説明するか。GDL他セクションへの参照）と `retell_frequency`（本人が繰り返し語る頻度）

レベル割り当ては L→Lv2、G→Lv1、E→Lv3 を仮置き。MEM-06 の検証結果によっては G を Lv1 の中心に据える判断もありうる。

スキーマ案（たたき台）は検討の §8-1 にある。

## MEM-05 静的スナップショットから動的な魂へ

### 現状

GDLは `meta.created_at` / `updated_at` を持つが、内容は特定時点の切り出しとして設計されている。更新ポリシーの記述はない。

### 論点

- 記憶の書き込みポリシー（何を覚えるか）をGDLが規定すべきか
- 忘却の設計（何を、どの速度で失うか）
- 人格レイヤ（GDL）と経験レイヤ（メモリストア）の責務分界
- GDLが「記憶ミドルウェアの設定ファイル」になる構図の是非

### 結論

■ **確定**（段階1の方針。実装は未着手）

**GDL本体を動的にする前に、提示プロトコルだけを動的にする段階を置く。** 記述の出自（実在か合成か）と提示の方式（全文静的注入か状況依存検索か）は独立した軸であり、static injection 批判は出自と無関係に成立する。したがってGDLは記憶を更新しなくても、提示の仕方を変えるだけでこの批判に応えられる。

| 段階 | GDL本体 | 提示の方式 | 得られるもの |
|---|---|---|---|
| 現在 | 静的 | 全文静的注入 | — |
| **段階1** | **静的（変更なし）** | **状況依存検索** | 状況に応じた人格の活性化。static injection 批判への応答 |
| 段階2 | 動的（記憶が追記される） | 状況依存検索 | 経験の蓄積。忘却の設計が必要になる |

**段階1はスキーマを一切変えずに実現できる。** 変えるのは読み込み側のプロトコルだけ。GDL 1.0 の仕様を壊さずに前進できる。

実装順は、まずプロンプト側（`prompts/generator/` のGPTsプロンプト群）で効果を確認し、効くと分かってから `_retrieval` セクションとしてスキーマ化する。Single Source of Truth の波及が大きいため段階的に入れる。

「GDL = 記憶ミドルウェアの設定ファイル」という構図の規定対象に、**検索関数の指定**を加える。

忘却の設計（段階2）は FSFM（[2604.20300](https://arxiv.org/abs/2604.20300)）の4機構——海馬的インデックス／エビングハウス忘却曲線／シナプス刈り込み／記憶の再固定化——を設計テンプレートとする。ACT-R の活性化式は個人差をパラメータで表す方法として有望。

## MEM-06 評価への影響（GDL_eval との整合）

### 現状

[eval/GDL_eval.md](../../eval/GDL_eval.md) は4層分解（Content/Reasoning/Style/Values）と2軸判別テスト、ベースライン正規化で忠実度を測る設計。記憶の有無は変数として考慮されていない。

### 論点

- 記憶を持つAIの回答は「答えを知っている」状態にならないか（判別軸の汚染）
- 「記憶なし忠実度」と「記憶あり忠実度」を分離すべきか
- 分離する場合、質問セット（GDL_eval_questions.json）側の改修範囲

### 結論

▲ **方針確定**（質問セット・ハーネスの改修は未着手）

- **LoCoMo-Plus（[2602.10715](https://arxiv.org/abs/2602.10715)）の Level-1 / Level-2 分離を、「記憶なし忠実度」「記憶あり忠実度」に対応させる。** Level-1 が事実想起、Level-2 が認知的記憶（causal / state-based / goal-oriented / value-based）
- **文字列一致メトリクスの交絡に対処する。** LoCoMo-Plus は、文字列一致が「記憶の忠実度」と「生成スタイル」を混同して評価を歪めると指摘している。これは GDL_eval の4層分解（Content / Reasoning / Style / Values）が抱える交絡と同じ問題。制約整合性による評価への置き換えを検討する
- **新規検証項目を立てる（優先度2）。** Lv1 の口調記述について、ラベル方式（現行）／エピソード接地方式（`general_events` の一人称段落）／両方 の3条件で文体類似度を比較する。PersonaGym の Linguistic Habits で記憶接地が +1.23 の差を出しているため、GDLのLv1が本当に効いているかを確かめる必要がある
- **PersonaGym / SimulatorArena 自体はGDLの評価には用いない。** 架空人格の「らしさ」しか測れず、実在の本人との忠実度を測れない。層別指標の切り方だけ参考にする

> ⚠️ 記憶の設計と評価フレームの再設計はセットでしか進められない、というのが出発点での認識。この認識は維持する。

## 参考文献

先行研究は [refs.md](refs.md) に分離（7分類・30件）。各章の検討時はそちらの「GDLの論点への当てはめ」節を参照する。

調査(2026-09-21)で判明した、検討の前提を揺さぶる3点：

1. **想起バイアスを記述しても再現されない可能性** — Simulating Human Memory with Language Models（[2605.25680](https://arxiv.org/abs/2605.25680)）は、フロンティアLLMが人間より記憶が良く、プロンプトでは人間的な忘却を誘導できないことを示した。作業記憶を制限すると量的には劣化するが、誤りの「種類」は人間と異なる。→ MEM-03 は記述設計の前に小さな再現実験が要る。
2. **逆向きのアプローチが既に存在する** — MemoryForge（[2608.00007](https://arxiv.org/abs/2608.00007)）は、静的なペルソナ記述を捨て、目標人格から逆算して生涯の自伝的記憶を合成し検索させる（memory-based conditioning）。

   > **訂正（2026-10-10）** — 当初これを「GDLの静的記述という立場そのものへの対抗仮説」と評価したが、これは要旨のみで判断した誤りだった。精読の結果、同論文が批判しているのは *descriptive conditioning*（特性ラベルと短いペルソナカードを静的に注入する手法群）であり、ベースラインも Big5Chat / DeepPersona / SimsChat / Anthology / FlatCard の薄いプロファイル型のみ。GDLのような厚い本人記述は比較対象に含まれていない。**GDLの立場そのものは否定されていない。** ただし「全文静的注入」という提示方式については批判が成立する（→ MEM-05）。詳細は [MemoryForge論文の解釈](studies/2026-10-08_memoryforge_MemoryForge論文の解釈/) §3。
3. **語り口の鋳型が個性を消す** — Mansfield et al.（[HSSC 2026](https://www.nature.com/articles/s41599-025-06426-y)）は、ChatGPTが元の話に無くても「贖罪型（成長・解決）」ナラティブ枠を押しつけること、人がそれを不自然と見抜くことを示した。→ MEM-04 の定型エピソードは、内容だけでなく語り口の鋳型も指定しないと汚染される。
