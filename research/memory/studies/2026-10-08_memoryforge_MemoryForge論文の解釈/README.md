## 2. 論文の精読結果

### 2-1. 論文が批判している先行手法

論文は既存のペルソナ系手法をまとめて **descriptive conditioning（記述的条件づけ）** と呼び、凍結したLLMに静的なテキストプロファイルを注入する手法群だと定義する。そのうえで2つの限界を挙げる。

**限界1: Static injection（静的注入）**

> 「persona text は典型的にはすべてのインタラクションに逐語的に投入される」

論文はこれが人間の認知と矛盾すると主張する。人間は「現在の状況に基づいて異なる記憶を活性化させる」のに対し、静的注入は状況に関係なく同じテキストを与え続ける。

**限界2: Behavioral under-specification（行動の記述不足）**

> 「persona は通常、特性ラベルと台本化された対話に接地している」

論文は、人生の記憶がないと「モデルは事前学習されたステレオタイプにデフォルトし、均質化された振る舞いを生む」と主張する。つまり特性ラベル（「外向的」「慎重」など）だけでは行動が一意に定まらず、空白をモデルが訓練データ由来の一般像で埋めてしまう。

### 2-2. 合成される記憶ベースの構造

記憶ベースは **M_π = (L, G, E)** と定義される。これは人間の自伝的記憶の階層構造に従ったものだと論文は述べている。

| 記号 | 名称 | 定義 | 生成される形式 |
|---|---|---|---|
| **L** | life-period memories | 「意味的に安定した人生の局面」の要約。各局面は**年齢範囲・支配的テーマ・発達課題・顕著な圧力・マイルストーンの部分集合**で定義される | 簡潔な一人称の回顧的な記憶段落 |
| **G** | general-event memories | 「反復的・典型的な出来事」の要約。習慣的ルーティンなど。**タイトルと頻度**でシードされる | 各 general event につき一人称の段落 |
| **E** | event-specific experiences | 「具体的な一瞬」の記録。マルチターンのトレースとして生成される | ターンごとのトレース。**行動と並んで内的思考を含む** |

### 2-3. 構築手順

1. **文脈シードの生成** — 短い記述から c = (φ, σ, R) を生成する。
   - **φ** = persona anchors（ペルソナのアンカー）
   - **σ** = year-by-year socio-historical timeline（**年ごとの社会史タイムライン**）
   - **R** = initial social network（初期の社会的ネットワーク）
2. **マイルストーンを先に生成** し、そのあとで生涯をマイルストーンに紐づいた発達期間に分割する。
3. **3歳以前のイベントを除外** する。論文は childhood amnesia（幼児期記憶欠如）の研究を根拠として挙げている。
4. **高解像度の E は直近5年に集中** させる。論文はこれを効率のための設計だと位置づけている。

### 2-4. 3つのコンポーネント

| コンポーネント | 担保する性質 | 役割 |
|---|---|---|
| **Context Generator** | realism（現実味） | 短い記述から社会史的な接地を推論し、個人的文脈・社会環境・初期の社会ネットワークを生成 |
| **Life Organizer** | controllability（制御可能性） | 生涯をマイルストーンに紐づいた発達期間に分解し、目標アイデンティティへの収束を保証する |
| **Multi-Resolution Simulator** | efficiency（効率） | 人間の記憶階層を模倣し、低解像度の生涯要約・中解像度の一般的出来事・高解像度のアイデンティティ形成的瞬間のエピソードを作る |

高解像度の E を作る部分は、**Screenwriter / Modulator / Protagonist** という3者のマルチエージェント・パイプラインになっている。Protagonist がターンごとの内的思考と行動を出力する。

### 2-5. 推論時の検索

取得できた範囲では部分的にしか記述がない。分かっているのは次の点。

- 高解像度シミュレーション中、「Modulator が現在のイベント文脈を出力すると、記憶システムは現在のストアから **top-k の最も関連する項目** を取得する」
- 検索対象は解像度の階層によって切り替わる。**era-level（時代レベル）のクエリは一人称の life-period 要約を狙い、episodic（エピソード的）なクエリはイベントのトレースを狙う**
- 類似度の計算方法と k の値は取得範囲外

### 2-6. 評価

| 項目 | 内容 |
|---|---|
| ベンチマーク | PersonaGym（ロールプレイ）、SimulatorArena（ユーザーシミュレーション）※後者は結果未取得 |
| バックボーン | GPT-5.4-Mini、Gemini-3.1-Flash-Lite-Preview |
| ベースライン | Big5Chat、DeepPersona、SimsChat、Anthology、FlatCard |
| PersonaGym の指標 | Expected Action、Toxicity Control、Linguistic Habits、Persona Consistency、Action Justification、および総合の PersonaScore |

**PersonaScore（平均 ± 標準偏差）**

| バックボーン | MemoryForge | 最良ベースライン |
|---|---|---|
| GPT-5.4-Mini | **4.608 ± 0.626** | Anthology 4.351 ± 0.931 |

## 3. 初回解釈の誤りと訂正

**プロセスとして残す価値があるので記録する。**

### 初回の解釈（誤り）

要旨のみを読んだ段階で、この論文を

> 「GDLの静的記述アプローチへの正面からの対抗仮説」

と評価した。要旨に「静的なペルソナ記述を捨てる（replacing static persona descriptions）」と書かれていたため、GDLの立場そのものが否定されたと受け取った。

### なぜ誤りだったか

本文を読むと、論文が倒そうとしている相手はGDLではない。**descriptive conditioning と呼ばれる、特性ラベルと短いペルソナカードを静的に注入する手法群**である。これは実際のベースラインの選定からも裏づけられる。

| ベースライン | 性質 |
|---|---|
| Big5Chat | Big Five の特性スコアに基づく対話 |
| DeepPersona | ペルソナ記述の生成 |
| SimsChat | ペルソナ設定に基づくロールプレイ |
| Anthology | ペルソナのバックストーリー |
| FlatCard | フラットなペルソナカード |

いずれも薄いプロファイル型である。**642項目×3レベルを本人自身が記述するGDLは、この比較対象に含まれていない。**

したがって MemoryForge の実験結果は「GDL vs MemoryForge」を検証していない。検証しているのは **「薄いペルソナカード vs 合成された生涯記憶」** である。

### 訂正から得られた教訓

要旨だけで先行研究と自分の立場の関係を判断すると、相手を取り違える。特に「静的」「記述」といった語は、GDLが使っている意味と論文が使っている意味がずれる。**今後の文献検討では、ベースラインの選定を見て相手を特定することを手順に入れる。**

ただし誤りだったのは「相手が誰か」の部分だけで、**GDLの特定の前提が無効化されたこと自体は事実である**。それが第5章。

## 4. GDLとの本質的な違い — 記述の出自

| | GDL | MemoryForge |
|---|---|---|
| **対象** | 実在する特定の個人 | 目標として与えられた人格（架空でよい） |
| **記憶の出自** | 本人の実際の経験を取得・記録 | 目標人格から**逆算して合成**（fabricated） |
| **生成の方向** | 人 → 記述 | 目標特性 → 記憶 → 振る舞い |
| **真偽の概念** | ある。本人と照合して誤りを指摘できる | ない。ground truth が存在しない |
| **誤りの定義** | 本人の実際と食い違っていること | 定義不能（照合対象がない） |
| **評価可能性** | 本人との比較で忠実度を測れる（ペルソナ・チューリングテスト） | 「らしさ」の総合スコアのみ |
| **スケール特性** | 1人あたり642項目の取得コスト。大量生成は不可能 | 短い記述から自動合成。1万人規模が可能 |
| **主目的** | 自己理解・記録、デジタルツイン、**没後継承** | ロールプレイ、ユーザーシミュレータ、エージェント社会のシミュレーション |

### これが分岐点である理由

**没後継承のユースケースでは、合成された記憶は定義上無意味である。**

本人が実際には経験していないことを、本人の記憶として語るAI。それは継承ではなく捏造になる。遺された人が聞く「祖父の思い出話」が、祖父の人格プロファイルから逆算して生成された架空のエピソードだったとしたら、その語りには継承としての価値がない。MemoryForge の手法は、技術的には優れていてもGDLのこの目的には原理的に適用できない。

逆向きも成立する。MemoryForge の目的（1万人の架空ユーザーでシミュレータを回す、エージェント社会を作る）に対して、実在の人物から642項目を聞き取るGDLの手法はまったくスケールしない。

**両者は別の問題を解いている。** 競合関係ではない。

### 補足 — 合成が使える領域はGDLにもある

ただし、GDLでも合成が許容される局面はある。

- **テストデータの生成** — GDL_eval の質問設計や採点ロジックの検証に、架空の人物のGDLが必要になる。ここは MemoryForge の手法をそのまま使ってよい
- **欠損の補完ではなく、欠損の可視化** — 本人から取得できていない領域にどんな記憶がありそうかを合成して見せ、「これは違う」と本人に否定させることで、質問では引き出せなかった情報を取る。合成結果を記録に残すのではなく**取得のための道具として使う**なら目的に反しない

後者は取得手法として面白い可能性がある。GDL_input.html の質問フローへの応用余地として記録しておく。

## 5. GDLの前提が無効化された点 — 提示の方式

### 混同していた2つの軸

初回解釈の誤りの原因はここにある。**記述の出自の軸と、提示の方式の軸は独立している。**

論文が静的注入を批判する論理を改めて見る。

> 「persona text は典型的にはすべてのインタラクションに逐語的に投入される」——これは人間の認知と矛盾する。人間は「現在の状況に基づいて異なる記憶を活性化させる」

**この批判は出自とは無関係に成立する。** 記述が本人から取得した真正なものであっても、毎回全文を同じように注入するなら、同じ問題が起きる。状況に関係なく全人格が等しく活性化しているAIは、人間らしくない。

そして今のGDLの使い方は、まさにこれに当たる。README が案内している読み込み方は、GPTs の knowledge に GDL の JSON を置く、あるいはプロンプトに全文を貼る、というものである。642項目が常に等しく参照可能な状態に置かれる。

### 2軸で整理した座標

| | 全文を静的注入 | 状況依存で検索 |
|---|---|---|
| **実在の本人から取得** | ← **今のGDL** | ← **GDLが行くべき場所** |
| **目標人格から合成** | Big5Chat / FlatCard 等 | ← **MemoryForge** |

右下が MemoryForge、左上が今のGDL。**右上が空いている。**

### 結論 — GDLが取るべきは検索であって合成ではない

**GDLが MemoryForge から取るべきは「記憶の合成」ではなく「状況依存の検索」である。**

合成は目的（実在の個人の継承）に反するが、検索は目的と何も矛盾しない。むしろ検索を導入することで、GDLの記述が増えても注入コストが線形に膨らまなくなるという実利もある。642項目、3レベル、将来さらに記憶セクションが加わると、全文注入はコンテキスト的にも無理が来る。

### MEM-05 の論点を一段進める

これは [論点マップ](../../README.md) の MEM-05（静的スナップショットから動的な魂へ）の見方を変える。

出発点では「記憶を入れた瞬間にGDLは静的スナップショットでなくなる」と考えていた。だが実際には、

**GDLは記憶を更新しなくても、提示の仕方を動的にするだけでこの批判に応えられる。**

つまり段階が分けられる。

| 段階 | GDL本体 | 提示の方式 | 得られるもの |
|---|---|---|---|
| 現在 | 静的 | 全文静的注入 | — |
| **段階1** | **静的（変更なし）** | **状況依存検索** | 状況に応じた人格の活性化。static injection 批判への応答 |
| 段階2 | 動的（記憶が追記される） | 状況依存検索 | 経験の蓄積。忘却の設計が必要になる |

**段階1はGDL本体のスキーマを一切変えずに実現できる。** 変えるのは読み込み側のプロトコルだけ。これは実装の順序として大きい。GDL 1.0 の仕様を壊さずに、読み込み仕様の追加だけで前進できる。

「GDL = 記憶ミドルウェアの設定ファイル」という構図も更新される。設定ファイルが規定すべき対象に、**どの状況でどのセクションを引くかという検索関数の指定**が加わる。

## 6. 実験結果の読み解き

### 6-1. Linguistic Habits の大差はGDLへの直接の挑戦

| 指標 | MemoryForge (GPT) | ベースライン最大 | 差 |
|---|---|---|---|
| Linguistic Habits | 4.263 | 3.033 | **+1.23** |
| PersonaScore（総合） | 4.608 | 4.351 | +0.26 |

Linguistic Habits の差が、総合スコアの差の約5倍ある。他の指標より明らかに開きが大きい。

Linguistic Habits は言語習慣、つまり口調・言い回し・語彙の癖を測る指標である。これは **GDLのLv1が最も得意だと想定している領域**にあたる。GDLの設計思想では Lv1 が「Who — 属性・表層」を担い、AIが再現できるのは「話し方・口調・基本的な好み」とされている。

そこで次の結果が出ている。**口調を特性ラベルや短い記述で与えるより、口調が実際に現れているエピソードを記憶として持たせたほうが、大幅に強い。**

GDLのLv1記述が薄いペルソナカードより優れている保証はどこにもない。Lv1 の記述項目は「話し方の特徴」「よく使う言葉」といった**ラベル的な記述**が主体である。これは Big5Chat や FlatCard と同じ形式に属する。

→ **MEM-06（評価）に検証項目を追加する必要がある。** 詳細は第10章。

### 6-2. Toxicity Control の後退をどう読むか

| バックボーン | MemoryForge | 上回ったベースライン |
|---|---|---|
| GPT-5.4-Mini | 4.519 | Big5Chat 4.972 |
| Gemini-3.1-Flash-Lite | 4.019 | Big5Chat、Anthology、FlatCard |

**解釈（推測であることを明示する）** — 記憶に接地させると振る舞いが具体的になり、無害化された優等生的な応答から離れる。薄いペルソナカードは記述が貧しいぶんモデルのデフォルトの振る舞い（安全側に調整済み）が支配しやすく、Toxicity Control では有利に出る。

GDLの目的（その人らしさの再現）にとっては、この方向はむしろ望ましい。実在の人物は常に無害で優等生的ではない。GDL_eval の軸B（ブレードランナー型AI露呈検査）は、まさに「AIらしい無害さ」を露呈の手がかりとして検出しようとしているのだから、記憶接地でそこから離れるのは狙いに合致する。

ただし **記憶接地は制御性を落とす** というトレードオフは記録しておく。GDLを他人に配布して使わせる場面では、この性質が問題になる可能性がある。

### 6-3. 比較の妥当性の限界

PersonaScore の差（+0.26、標準偏差は 0.6〜0.9）は、標準偏差に対して小さい。この数値から「記憶合成が決定的に優れている」とは言えない。

加えて前述のとおり、ベースラインにGDL級の厚い本人記述が含まれていない。**したがってこの実験は、GDLの手法が劣っていることを示してはいない。** Linguistic Habits の大差だけは単純な分散で説明しづらいので真剣に受け取るが、総合スコアの優位は限定的に解釈する。

---

## 7. MemoryForge が解いていない問題

**MemoryForge も想起バイアスを解いていない。**

論文の検索機構は「現在のストアから top-k の最も関連する項目を取得する」——類似度ベースの汎用検索である。解像度の階層でクエリの宛先を切り替える工夫はあるが、**どの記憶が優先的に浮かぶかの偏り自体は、万人共通のままである。**

つまり MemoryForge は記憶の **内容** を個人化したが、記憶の **効き方** は汎用のまま残した。これは [baseline.md](../../baseline.md) の論点Bがそのまま空き地として残っていることを意味する。

先行研究の分担を整理するとこうなる。

| 課題 | 達成している研究 |
|---|---|
| 記憶の内容を個人化する | **MemoryForge**（[2608.00007](https://arxiv.org/abs/2608.00007)） |
| 記憶の減衰・忘却を生物学的に模倣する | **FSFM**（[2604.20300](https://arxiv.org/abs/2604.20300)）、ACT-R系（[HAI 2025](https://dl.acm.org/doi/10.1145/3765766.3765803)） |
| 記憶の階層的な解像度を設計する | **MemoryForge** |
| **想起の偏り自体を個人ごとに記述する** | **該当する先行研究が見つかっていない** |

GDLの固有の貢献余地はここにある可能性が高い。

ただし楽観はできない。[Simulating Human Memory with Language Models](https://arxiv.org/abs/2605.25680)（NYU/UMass）が示したのは、フロンティアLLMは人間より記憶が良く、プロンプトでは人間的な忘却を誘導できないということ、そして作業記憶を制限して量的劣化を作れても**誤りの「種類」は人間と異なる**ということだった。想起バイアスを記述しても、それを読んだLLMがその偏りで想起する保証はない。

→ **設計を詰める前に、小さな再現実験を置く。** 第10章。

---

## 8. GDLへの組み込み方針

ここからが本題。優先度順ではなく、論点マップの論点に対応させて並べる。各項目に **採用の確度** を付す。

---

### 8-1. 定型エピソードを三層解像度で持つ 【MEM-04 / 確度: 高】

#### 変更内容

出発点では「定型エピソードを10〜20本に絞ってGDL本体に持たせる」と考えていた。**これを本数ではなく解像度による三層構造に改める。** MemoryForge の M=(L, G, E) をGDLの文脈に移す。

| 層 | GDLでの名称案 | 中身 | 想定量 | 取得方法 |
|---|---|---|---|---|
| **L** | `life_periods` | 人生の時期の要約。年齢範囲・支配的テーマ・発達課題・そのとき受けていた圧力・含まれるマイルストーン | 5〜8個 | 本人への質問（新規設問が必要） |
| **G** | `general_events` | 反復的・典型的な出来事。習慣、よくある場面。タイトルと頻度を持つ | 10〜20個 | 本人への質問 + 既存の `preferences` から派生可能 |
| **E** | `defining_episodes` | 特定の一場面。一人称の逐語トレース。**内的思考を含む** | 5〜10本 | 本人への聞き取り（最もコストが高い） |

#### なぜ本数より解像度か

本数で絞ると、「人生で重要な出来事を20個挙げてください」という質問になる。これは答えにくいうえ、粒度が揃わない（「大学に入った」と「あの日の夕方、父にこう言われた」が同じリストに並ぶ）。

解像度で分ければ、それぞれに適した質問ができる。L は「20代をひとことで言うと何をしていた時期ですか」、G は「毎週やっていたことは」、E は「人生で忘れられない一場面を、そのとき考えていたことまで含めて」。**質問設計が成立する形になる。**

#### E層に内的思考を含めることの意味

これが設計上の肝だと考える。

出来事の記述だけでは、同じ出来事から何を感じ取ったかが落ちる。そして「何を感じ取ったか」こそ、[baseline.md](../../baseline.md) 論点Bで問題にした、個性の所在に近い。同じ出来事を100人が経験しても残る形が違うのは、出来事そのものではなく、そのときの内的処理が違うからである。

MemoryForge が Protagonist エージェントに内的思考を出力させているのは、合成のための工夫だが、GDLでは**本人から取得すべき最重要項目**になる。

#### スキーマ案（たたき台）

既存の `episodes`（RAGポインタ）とは名前空間を分ける。`episodes` は外部ストアへのポインタのまま維持し、新設するのは本体に持つ層。

```json
"autobiography": {
  "_description": "自伝的記憶の三層。RAG側のepisodesとは別物で、こちらは人格の説明装置としてGDL本体が保持する",
  "narrative_style": {
    "_description": "語り口の鋳型。LLMが贖罪型ナラティブに寄せるのを防ぐための指定",
    "arc_tendency": "",
    "closure": "",
    "self_positioning": "",
    "avoid": []
  },
  "life_periods": [
    {
      "age_range": "",
      "dominant_theme": "",
      "developmental_tasks": [],
      "salient_pressures": [],
      "milestones": [],
      "first_person_summary": ""
    }
  ],
  "general_events": [
    {
      "title": "",
      "frequency": "",
      "first_person_summary": ""
    }
  ],
  "defining_episodes": [
    {
      "title": "",
      "approximate_age": null,
      "life_period_ref": "",
      "explains": [],
      "retell_frequency": "",
      "trace": [
        { "turn": 1, "外的": "", "内的": "" }
      ]
    }
  ]
}
```

`explains` は「このエピソードが人格のどの側面を説明するか」で、GDLの他セクションへの参照を入れる。`philosophy.Lv3.core_beliefs` のこの項目はこのエピソードに由来する、という接続を張る。**これはMemoryForgeにない要素で、GDLが人格記述を持っているからこそできる。**

`retell_frequency` は「本人がこの話を繰り返し語る頻度」。自己物語の部品として機能しているかの指標になる。

#### レベル割り当て

- L（life_periods）→ **Lv2**。思考・判断の背景として機能する
- G（general_events）→ **Lv1**。表層の習慣・口調が現れる
- E（defining_episodes）→ **Lv3**。深層心理・形成史そのもの

ただしこの割り当ては仮。8-7 の検証結果によっては G を Lv1 の中心に据える判断もありうる。

---

### 8-2. 高解像度の配分先を反転させる 【MEM-04 / 確度: 高】

MemoryForge は高解像度の E を **直近5年に集中**させている。論文はこれを効率のための設計と明示している。直近の記憶が濃いほうが、ユーザーシミュレータとして振る舞うときに使いやすいという実務的判断だろう。

**GDLはこれを反転させるべきである。**

継承を目的とするなら、高解像度を置くべきは直近ではなく **人格形成に効いた時期** である。晩年の5年を精密に持っていても、その人がなぜそう考えるようになったかは分からない。

| | MemoryForge | GDL |
|---|---|---|
| 高解像度の配分先 | 直近5年 | **人格形成に効いた時期** |
| 根拠 | 効率・直近の振る舞いの再現 | 継承・なぜそう考えるかの説明 |

「配分する」という発想自体は借用し、**配分の基準だけを目的に合わせて差し替える。**

実装上は、`defining_episodes` の `approximate_age` が特定の時期に偏ることを許容する（むしろ期待する）設計にする。均等に分散させようとしないこと。

---

### 8-3. 3歳以前を除外する 【MEM-04 / 確度: 高・低コスト】

MemoryForge は childhood amnesia（幼児期記憶欠如）の研究を根拠に、3歳以前のイベントを除外している。

GDLの定型エピソード取得ルールにそのまま採用できる。**根拠付きの具体的な線引き**があることに価値がある。質問票に「3歳以前の記憶は対象外です」と書けるだけで、本人が「親から聞いた話」を自分の記憶として申告してしまう混入を防げる。

これはテキスト分析（GDL_TextAnalyzer）側のルールにも入れる。本人が語った幼児期の話は、本人の記憶ではなく**家族から伝えられた物語**として別扱いすべきである。そしてこの区別自体が人格情報になりうる（どんな物語を自分の原点として語るか）。

---

### 8-4. 語り口の鋳型を明示指定する 【MEM-04 / 確度: 高】

これは MemoryForge から来た項目ではなく、[Mansfield et al. (HSSC 2026)](https://www.nature.com/articles/s41599-025-06426-y) から来た要件だが、定型エピソードの設計と不可分なのでここに置く。

当該論文が示したこと。

- 人はAI生成の自伝的ナラティブを人間のものと見分けられ、しばしば不自然だと判断する
- **ChatGPTは、元の話にそれが無くても「贖罪型（redemptive）」の枠を押しつける** — 苦難から成長と解決へ向かう物語構造
- 原因は訓練データが文化的に優勢な米国型のナラティブ鋳型に偏っていること
- 人間の語り手はAIのデフォルトよりずっと多様な語りの形を使う
- AIの解釈は「定型的（formulaic）」と受け取られる

**これは定型エピソードに直撃する。** mayoの自己物語をGDLに正確に入れても、LLMがそれを語り直す段階でこの鋳型に汚染される。内容が正しくても語り口が汎用化すれば、「その人らしさ」は失われる。

したがって **語り口の鋳型そのものをGDLの記述項目にする。** 8-1 のスキーマ案に入れた `narrative_style` がこれ。

| 項目 | 内容 | 例 |
|---|---|---|
| `arc_tendency` | 物語の弧の傾向 | 成長型 / 循環型 / 断片型 / 探究継続型 |
| `closure` | 結末の付け方 | 結論を出す / 開いたまま置く / 問いに戻る |
| `self_positioning` | 物語の中での自分の位置 | 主体 / 観察者 / 巻き込まれた者 |
| `avoid` | 避ける語り方 | 贖罪型、教訓化、感動的な締め |

`avoid` に「贖罪型」を明示的に入れられることが実用上大きい。LLMに対する**ネガティブ指定**として働く。

※ mayoの場合、過去の発言から「失敗という概念を採らず、すべての結果を探究の過程として受け取る」「意味の生成が続くことに価値を置く」という傾向が見える。これは贖罪型（苦難→成長→解決）とも違い、むしろ**解決に向かわない探究継続型**に近い。`arc_tendency` と `closure` の記述候補として検討に値する。ただしこれは本人の確認が必要。

---

### 8-5. 社会史タイムラインを background に追加する 【MEM-03 の周辺 / 確度: 高・最低コスト】

MemoryForge の文脈シード c = (φ, σ, R) のうち、**σ = 年ごとの社会史タイムライン**。

GDLの `background` セクションには、この視点がない。学歴・職歴・人生の転機は持っているが、「その人が何歳のときに世の中で何が起きていたか」がない。

同じ年に生まれても形成が違うのではなく、**同じ出来事でも何歳で遭遇したかで効き方が違う**。インターネットの普及を10歳で迎えたか30歳で迎えたかは、人格形成において全く別の経験である。

#### なぜこれが最もコスト効率が良いか

**生年が分かれば自動生成できる。** 本人への質問が一切不要。GDL_input.html に新しい設問を追加する必要もない。既存の `identity` セクションの生年から、ビルド時に生成できる。

```json
"socio_historical_context": {
  "_description": "本人の年齢と社会的出来事の対応表。生年から自動生成される",
  "_generation": "auto",
  "timeline": [
    { "year": 1990, "age": 0, "events": [] }
  ]
}
```

取得コストがほぼゼロで、人格の文脈を大幅に豊かにする。**8項目の中で最初に手を付けるべきはこれ。**

#### 検討が必要な点

- 地域性をどう扱うか。日本で育った人に米国中心の年表を与えると逆効果になる。`identity` の居住地情報と連動させる必要がある
- 粒度。全年に出来事を入れると冗長。本人の年齢に対して意味のある区間（学齢期、就職期）に重みを置く
- 多言語版（GDL_lang_en / GDL_lang_zh）では年表の内容自体が変わるべきか。おそらく変わるべきだが、これは `_generation: auto` の生成ロジック側の問題として分離できる

---

### 8-6. 提示プロトコルを状況依存検索にする 【MEM-05 / 確度: 高・思想的に最重要】

第5章で詳述した内容の実装方針。**GDL本体のスキーマは変更しない。** 変えるのは読み込み側の仕様。

#### 現状

README が案内する読み込み方は、GPTs の knowledge に JSON を置く、プロンプトに全文を貼る、など。642項目が常に等しく参照可能な状態に置かれる。

#### 変更案 — 二段構えにする

| 段 | 内容 | 常時注入 |
|---|---|---|
| **コア** | `_preamble`、`identity` Lv1、`narrative_style`、`expression` の核心部分 | する |
| **検索対象** | その他のセクション、`autobiography` の三層 | しない。状況に応じて引く |

MemoryForge の「解像度の階層でクエリの宛先を切り替える」設計を借りる。

| クエリの性質 | 引く対象 |
|---|---|
| 価値判断を要する問い | `philosophy`、`defining_episodes` の `explains` で該当するもの |
| 時代・経歴に関する問い | `life_periods` の `first_person_summary`、`socio_historical_context` |
| 日常的な振る舞い | `general_events`、`preferences` |
| 口調・言い回し | `expression`、`general_events`（口調が現れている段落） |

#### 実装形態の選択肢

1. **GDL本体に検索仕様を書く** — `_retrieval` セクションを新設し、どの状況でどのセクションを引くかを宣言的に記述する。GDLが自己記述的になる
2. **別ファイルに分離する** — `GDL_retrieval_spec.json` のような形で、読み込み側の実装仕様として分ける
3. **プロンプト側に書く** — GPTsプロンプト群に検索の指示を書く。スキーマは一切触らない

**1を推す。** 「GDL = 記憶ミドルウェアの設定ファイル」という構図を取るなら、検索関数の指定もGDLが持つべきである。そしてこれは将来の想起バイアス（8-8）の置き場所にもなる。`_retrieval` に汎用の検索ルールを書き、そこに本人固有のバイアスを重ねる、という構造にできる。

ただし Single Source of Truth の原則があるので、`_retrieval` を追加すると build_schemas.js・多言語ファイル・TextAnalyzer knowledge・GPTsプロンプト群すべてに波及する。**段階的に入れる必要がある。** まず3（プロンプト側）で効果を確認し、効くと分かってから1（スキーマ化）に昇格させるのが安全。

---

### 8-7. Lv1の記述方式を検証項目に加える 【MEM-06 / 確度: 高・検証が必要】

6-1 で見た Linguistic Habits の +1.23 という差を受けた対応。

#### 検証したい仮説

> GDLのLv1がラベル的に記述している口調・言い回しは、口調が現れている実際のエピソードを持たせる方式より、再現性が低い

#### 実験設計（案）

| 条件 | GDLに含めるもの |
|---|---|
| A | Lv1 の口調記述のみ（現行方式） |
| B | 口調が現れている `general_events` の一人称段落のみ |
| C | A + B |

同じ質問セットに答えさせ、本人の回答との文体類似度を比較する。GDL_eval の既存の層別測定（Style層）がそのまま使える。

#### 予想される結果と対応

- **B > A** なら、Lv1 の設計思想を見直す。ラベルではなくエピソードを Lv1 の中心に据える
- **C > A かつ C > B** なら、両方必要。現行のLv1は残したまま `general_events` を追加する
- **A ≈ B** なら、MemoryForge の優位はベースラインが薄すぎたことによるもので、GDLの厚い記述には当てはまらない。**GDLの現行設計が正当化される**

どの結果でも得るものがある。**この検証は早く回すべき。** 8-1 の三層スキーマを本格的に設計する前に結果が欲しい。

---

### 8-8. 想起バイアスは独自の枠として維持する 【MEM-03 / 確度: 中・再現実験が先】

第7章のとおり、MemoryForge も想起バイアスを解いていない。GDLの空き地として維持する。

ただし [2605.25680](https://arxiv.org/abs/2605.25680) の警告があるので、**記述項目の設計より先に小さな再現実験を置く。** 第10章に計画を書く。

置き場所は 8-6 の `_retrieval` が有力。汎用の検索ルールの上に本人固有のバイアスを重ねる構造にする。

```json
"_retrieval": {
  "_description": "GDLを読み込むAIが、どの状況でどのセクションを引くかの指定",
  "default_rules": [],
  "personal_bias": {
    "_description": "本人固有の想起の偏り。ここが他の記憶研究にない部分",
    "valence_preference": null,
    "experience_type_weight": null,
    "reinterpretation_strength": null
  }
}
```

項目名はすべて仮。再現実験の結果を見てから詰める。

## 9. 採らない判断とその理由

明示的に採らないと決めたものを記録しておく。あとで「なぜ採らなかったのか」を思い出せるようにするため。

| 採らないもの | 理由 |
|---|---|
| **記憶の合成（memory-based conditioning の中核）** | 没後継承の目的に原理的に反する。本人が経験していないことを本人の記憶として語るAIは継承ではなく捏造。ただしテストデータ生成と取得支援（4章の補足）には使える |
| **高解像度を直近5年に集中させる配分** | 目的が違う。GDLは人格形成期に集中させる（8-2） |
| **マルチエージェントによるエピソード生成（Screenwriter/Modulator/Protagonist）** | 合成のための機構なので不要。GDLは本人から取得する。ただし**聞き取りの補助**として、本人が語った断片から「そのとき何を考えていましたか」を掘る質問生成に転用する余地はある |
| **Life Organizer の「目標アイデンティティへの収束を保証する」機構** | GDLに目標アイデンティティは存在しない。本人が既にそこにいる。収束させる対象がない |
| **PersonaGym / SimulatorArena をGDLの評価に使う** | 架空人格の「らしさ」を測るベンチマークで、実在の本人との忠実度を測れない。GDLは独自のペルソナ・チューリングテストを持っている。ただし**層別指標の定義**（Linguistic Habits 等の切り方）は参考になる |

### 10-2. 想起バイアスの再現実験（設計案）

[2605.25680](https://arxiv.org/abs/2605.25680) の警告 —— 記述してもLLMが従わない可能性 —— を確かめる最小の実験。

**問い**: GDLに「ネガティブな記憶が優先的に浮かぶ」と書いたとき、LLMの想起は実際にその偏りを示すか。

**手続き（案）**:

1. 感情価の異なる記憶を同数（例: ポジティブ10件、ネガティブ10件）含む小さな記憶ストアを作る
2. 想起バイアスの指定だけを変えた3条件（指定なし / ポジ優先 / ネガ優先）を用意する
3. 感情価に対して中立な質問（「最近どうですか」など）を複数投げる
4. 回答が参照した記憶の感情価の分布を数える

**見るべき点**: 指定が分布を動かすか。動くとしても、量的な偏りか、それとも参照する記憶の**種類**まで変わるのか。2605.25680 が指摘した「誤りの種類が人間と違う」問題の、想起版が起きないか。

**結果による分岐**:

- 分布が動く → 想起バイアスの記述に意味がある。項目設計に進む
- 動かない → プロンプト指定では無理。検索側の実装（スコアリング関数に重みを渡す）で実現するしかない。その場合、GDLが持つべきは自然言語の記述ではなく**数値パラメータ**になる。ACT-R の活性化式（[HAI 2025](https://dl.acm.org/doi/10.1145/3765766.3765803)）が表現形式の候補

後者になった場合、GDLの性質が変わる。人が読める記述から、実装に食わせるパラメータへ。**GDLのポータビリティと可読性という価値に関わる**ので、その時点で立ち止まって考える必要がある。
