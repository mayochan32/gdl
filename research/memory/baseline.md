## 0. 現状認識（事実）

`GDL_schema.json` の11セクションのうち、`episodes` だけが他と構造が違う。

| | 他の10セクション | `episodes` |
|---|---|---|
| 構造 | Lv1 / Lv2 / Lv3 の三層 | 三層なし |
| 中身 | 計642項目以上の具体的記述項目 | `storage_type: "RAG"` と `sources` のみ |
| 役割 | 人格の記述 | 記憶の**置き場所のポインタ** |

`sources` に列挙されているのは `conversation_log` / `photo_metadata` / `diary_or_notes` / `sns_posts` の4種。いずれも `description` と `location` が空のテンプレート状態。

このほか `gdl.preferences.Lv3.sensory_memories` に感覚的記憶の配列があるが、これは嗜好セクションの一部であり、記憶セクションとしては設計されていない。

**つまり現状のGDLは「記憶は外部に置く、GDLはそのポインタだけ持つ」という暫定的な設計判断のまま止まっている。**

## 1. 出発点となる4つの論点

### 論点A — 外部化の判断自体は妥当

記憶は無限に増える。GDLは人が読めてポータブルであることに価値がある。全部を本体に抱え込めば破綻する。
→ **外部化そのものは維持してよい。** 問題は外部化の結果として抜け落ちたものにある。

### 論点B — 抜けているのは「記憶の内容」ではなく「記憶の効き方」

同じ出来事を100人が経験しても、残る形は全員違う。何を鮮明に覚え、何を都合よく書き換え、どんな文脈でどの記憶が引き出されるか——その偏りこそ個性に近い。

RAGに生ログを積んでベクトル検索でトップkを引くのは「万人共通の想起エンジン」を使うということで、そこに本人らしさは一切入らない。

→ GDLが記述すべきは**想起バイアス**。たとえば、
- どの感情価の記憶が優先的に浮かぶか
- 成功体験と失敗体験のどちらを判断材料に使う癖があるか
- 古い記憶をどれくらい現在の解釈で上書きするか

### 論点C — 「定型エピソード」は本体に入れる価値がある

人は自分を説明するとき同じ話を繰り返す。これは記憶というより**自己物語**の部品で、人格の説明装置として機能している。

10〜20本に絞って構造化し、GDL本体に持たせる。RAGの数万件とは役割が全く違うので、同じ `episodes` に混ぜるべきではない。

### 論点D — 記憶を入れるとGDLは静的スナップショットでなくなる

現在のGDLは「ある時点の魂の切り出し」。記憶が更新されるなら、**何を覚え何を忘れるかの方針（忘却の設計）**までGDLが規定することになる。

これは自然な着地でもある。GDLが「記憶ミドルウェアの設定ファイル」になる構図：

```
人格レイヤ（GDL）          ← 記憶の読み書きポリシーを規定する
       ↓ 制御
経験レイヤ（メモリストア）  ← 実際のエピソードが蓄積される
```

現行のLLMのメモリ機能（事実の羅列＋タグ）の一段上のレイヤになれる。

## 2. 出発点で認識している最大のリスク

**GDL_eval との相性が悪い。**

忠実度評価で「その人らしさ」を測っているのに、記憶を持たせた再現は、答えを知った状態で答えているのと変わらなくなる場面がある。判別軸が記憶の有無で汚染される。

→ 記憶を導入するなら、評価フレーム側も「記憶なし忠実度」と「記憶あり忠実度」に分けて再設計する必要がある。**記憶の設計と評価の再設計はセットでしか進められない。**
