Evaluation Framework

ペルソナ
チューリングテスト

GDLを組み込んだAIが、本当にその人のように振る舞うか——その再現の忠実度を定量的に測定する評価フレームワーク。

Overview

なぜ評価が必要か

GDLで「個性を記述できた」ことと、そのデータで「AIが本当にその人らしく振る舞う」こととは別問題です。「らしさ」を印象論で語れば「なんとなく似ている／似ていない」で終わってしまいます。

基本アイデアはシンプル——本人とGDL-AIに同じ質問をぶつけ、回答がどれだけ似ているかを測る。ただし素朴に類似度を測るだけでは確実に誤るため、本フレームワークはその落とし穴を回避する設計原則を体系化しています。評価は終着点ではなく、GDLをブラッシュアップするための計測器です。

何を測るのか — 4つの層

「その人らしさ」を単一スコアに潰さず、独立した4層で評価します。

層内容
Content立場・選択（どちらを選ぶか、賛成か反対か）
Reasoning推論パターン（なぜそう考えるか、論の運び方）
Style文体・声（口調、語彙、文の長さ、言い回しの癖）
Values価値観（判断の裏にある優先順位）

🎸 アナロジー：カバーバンドの評価。「正しい音を弾いたか（Content）」「アレンジが本物っぽいか（Reasoning）」「声色が本人か（Style）」を別々に採点し、最終試験は「目を閉じたファンが偽物だと気づくか」——これが次の2軸です。

Two Axes

評価の2軸 — 同一性と人間性

「その人らしさ」の最終判定は、直交する2つの軸で構成されます。これが本フレームワークの核心です。

🎭

軸A — 同一性

「これは"その人"か？」 本人とGDL-AIの回答を並べ、本人をよく知る人に「どちらが本物か」を当てさせる。正答率が50%（チャンス）に近いほど区別不能＝高再現。

🤖

軸B — 人間性 / AI露呈

「そもそも人間として通るか？」 内容が似ていてもAI特有の癖が出れば失格。『ブレードランナー』のフォークト＝カンプフ検査と同じ発想で、AIだと露呈しないかを測る。

軸Bで検出すべき典型的な「AIの尻尾」：過剰な両論併記／やたら丁寧で起伏のないレジスター／ヘッジ表現の多用／人間的な「ムラ」の欠如。判定者のAI正答率が低い（チャンスに近い）ほど良いという、軸Aとは最適化方向が逆の指標です。

軸B：人間として通る ▲ 人間だが別人 │ 本人として通る （文体は人間的だが │ （理想：A∧B 両立） "その人"ではない） │ ─────────────────────┼─────────────────────▶ 軸A：その人と同一 │ AIだとバレる │ 内容は本人的だが （論外） │ AIだと露呈する │

合格条件は「軸A ∧ 軸B」の両立。どちらか一方では不十分です。

Baseline

ベースライン — 生スコアは無意味

「類似度は0.82でした」と言われても、それが高いのか低いのか判断する基準がありません。最低2本の基準線が必要です。

基準線測り方意味
天井本人 vs 本人（日を変えた test-retest）人は自分自身ですら完全には一貫しない。GDL-AIが超えられない上限
床素のAI（GDL無し） vs 本人GDLが何も足していない状態
弁別チェック他人のGDL-AI vs 本人固有の信号を捉えているか（別人では似ないはず）

最終指標は生スコアではなく、床↔天井の間で正規化した GDL Fidelity Score にします。

GDL Fidelity Score = (GDL-AIのスコア − 床) / (天井 − 床) 0.0 = 素のAIと変わらない（GDLが効いていない） 1.0 = 本人の自己一致度に到達（理論上の上限）
Question Design

質問設計の考え方

① 弁別力 — 答えが割れる質問だけが価値を持つ

「人を殺すのは悪いか？」のように全員が同じ答えを返す質問は、個人差の分散がゼロで測定上無意味。人によって答えが割れる質問だけが個性を測れます。

② ホールドアウト分割 — 暗記でなく汎化を測る

GDLに既に書いてある内容を問うと「記憶の再生」を測るだけ。In-GDL質問（想起精度）とHeld-out質問（GDL未学習の新規状況＝真の汎化）に分け、後者で本人と一致してこそ「らしさの再現」と言えます。

③ 2層分離 — 質問と「答えの鍵」を分ける

弁別力は質問と母集団の性質であり、特定個人とは無関係です。そこで万人共通の普遍質問バンクと、被験者ごとのanswer key（本人の回答＝gold）を別ファイルに分離します。ありがちな失敗は「赤いアメ車で」のように答えを質問に焼き込むこと——質問は普遍形にし、その人らしさはanswer key側に置きます。

④ ハイブリッド形式と傾向採点

自由記述だけでは「回答の手間」と「評価のブレ」が大きい。そこで選択式を主力に、文体・人間性を測る自由記述を少数の専用層として残します。全部を選択式にすると軸B（人間かAIか）と文体が測れず、しかもGDL-AI側が楽になって忠実度が過大評価されるためです。

形式役割測れる層
選択式（4択＋どれでもない）主力。定量・容易・大量化Content / Values
自由記述（少数）軸Bと文体の死守Style / 軸A / 軸B

⑤ 軸タクソノミーと大量プール

質問は思いつきでなく、性格の次元（trait_axis）を先に体系化し「どの軸を測るプローブか」を明確に設計します（8カテゴリ×5軸＝40軸）。1軸をシナリオ領域を変えて言い換えることで、被覆を保ったまま大量のバリエーション（目標〜1000問）を生成。出題は各カテゴリ・軸から固定数を引く層化サンプリングとし、毎回違う質問でも同じ次元をカバーします。これにより同じ人やAIが複数回受験でき、人間のブレを平均化できます。

⑥ 選択肢のランダム順

選択肢を「弱→強」で並べると惰性で同じ記号を選びがち（レスポンスセット・バイアス）。表示順はランダム化し、記号A〜Dが強弱を表さないようにします。採点は記号でなく軸座標 axis_pos で行うため、順序を変えても結果は不変です。

Scoring Logic

分析の仕方 — 採点ロジック

① 質問単位の類似度

各選択肢には性格軸上の座標 axis_pos ∈ [0,1] が付いています。本人とGDL-AIの回答について：

sim(q) = 1 − |axis_pos_本人(q) − axis_pos_AI(q)|

完全一致なら 1.0、軸上で隣なら部分点、対極なら 0。ゼロイチでなく「傾向の近さ」を定量化します。「どれでもない(X)」は axis_pos=null のため距離計算から除外し、件数だけログします。

② 傾向プロファイルと距離

回答を軸／カテゴリで平均し、傾向プロファイルを作ります。本人 P とAI Q の類似度は：

profile_sim = 1 − mean |P[c] − Q[c]| （c: 共有カテゴリ）

質問単位の平均は「どこでズレたか」、プロファイル距離は「人格の形そのものがどれだけ似ているか」を表します。出題が毎回変わってもプロファイル距離は安定します。

③ ベースライン正規化

生スコアを床（素のAI）と天井（本人 test-retest）で正規化し、単一指標 GDL Fidelity Score を得ます。

Harness

評価ハーネス

このパイプラインを回す参照実装が GDL_eval_harness.py です（Python標準ライブラリのみ・依存なし）。質問バンクと answer key を入力に、4つのサブコマンドを提供します。

サブコマンド役割ロジック
profile傾向プロファイル表示回答の axis_pos をカテゴリ／軸で平均し、全体平均とバーを出力
score本人 vs AI の採点質問別類似度・カテゴリ別・プロファイル距離。--baseline で正規化 Fidelity Score も算出
sample層化サンプリング出題各カテゴリからN問抽出。--shuffle で選択肢順をシャッフルしA〜D再付番（Xは末尾固定）
styleopen回答の文体計量文字数・文数・平均文長・文字bigram多様度を本人vsAIで比較

採点は記号でなく axis_pos を参照するため、選択肢順のシャッフルは結果に影響しません。出力はカテゴリ別の昇順ソートで「どこが弱いか」が一目で分かり、それがそのままGDL改善ポイントになります。

# 使い方の例 python GDL_eval_harness.py profile --bank GDL_eval_questions.json --key GDL_eval_key_mayo_v03.json python GDL_eval_harness.py score --bank ... --person <本人key> --ai <GDL-AI key> --baseline <素のAI key> python GDL_eval_harness.py sample --bank ... --per-category 3 --shuffle --seed 1
