# ペルソナ チューリングテスト — 運用手順（v1.2 / 軸A）

GDLを組み込んだAIが本人をどれだけ再現できるかを、A/B/C 比較により定量測定する。

- **A（床）**: GDL無しの素のAI　**B**: GDL有りのAI　**C（gold）**: 人間本人
- 指標: `GDL Fidelity Score = (sim(B,C) − sim(A,C)) / (1 − sim(A,C))`（1に近いほどGDLが効いている）
- 測定対象は **軸A（同一性）** のみ（軸B＝人間性は今後）。
- 出題数は被験者が選択：**短縮版40問**（各軸1問）／**標準版80問**（各軸2問）

## 実行形態

**`PTT_prompt.txt` を、コード実行が使えるAIチャットに貼り付けて実施する。**

2026-08、OpenAIが個人アカウント（Free/Go/Plus/Pro）での**GPTs新規作成・公開を停止**したため、専用GPTを前提としない方式に変更した。既存GPT（GDL Generator など）は引き続き利用可能。詳細は `PTT_SETUP.md` を参照。

この方式は特定のサービスに依存しない。コード実行（Code Interpreter／データ分析）が使えるAIチャットであれば動作する。Business等のワークスペースがある場合は、同じプロンプトをGPTのInstructionsに貼っても使える。

## 構成ファイル

| ファイル | 役割 | 読む人 |
|---|---|---|
| `PTT_prompt.txt` | AIチャットに貼り付ける進行プロンプト本体 | 被験者（コピーするだけ） |
| `PTT_SETUP.md` | 実施方法・設計メモ・限界 | 運用する人 |
| `ptt_scorer.py` | 採点エンジン（被験者が添付する） | — |
| `../GDL_eval_pool.json` | 質問プール1000問（被験者が添付する） | — |
| `../ptt_guide.html` | 被験者向けガイド。**配るのはこれ1つでいい** | 被験者 |
| `../eval.html` | 評価フレームワークの設計思想 | 興味のある人 |

## 被験者の使い方

配布するのは `../ptt_guide.html`（GitHub Pages: https://mayochan32.github.io/gdl/ptt_guide.html ）。ファイルのダウンロードリンクとプロンプトのコピーボタンが載っているので、これ1枚で完走できる。以下はその要約：

1. 別GPT「GDL Generator」で自分のGDL（JSON）を作り、`.json` ファイルとして保存する。
2. `GDL_eval_pool.json` と `ptt_scorer.py` をダウンロードし、`PTT_prompt.txt` の全文をコピーする。
3. AIチャットで**新規の会話**を開き、**2ファイルを添付**したうえで**プロンプトを貼り付けて送信**する（同じ1通でよい）。
   - ※GDLはまだ添付しない。先に添付すると床(A)が汚染され、測定が成立しない。
4. 出題数（40問 or 80問）を選ぶ。
5. AIが自動で進める:
   - 出題サブセットを層化抽出（各軸1問 or 2問）
   - A（素のAI）を生成（GDL不在のクリーンな床）→ **「GDLを添付してください」と依頼** → 添付 → B（本人として）を生成
   - 同じ問題に**被験者自身が回答**（C）。**1問ずつ提示され、記号1文字（A/B/C/D/X）を送るだけ**で次へ進む。
   - 採点 → レポート表示＋ `ptt_result.json` ＋ `ptt_report.md`

> 注：チャット内にクリック可能なボタンは出せないため、回答は記号1文字の送信で行う。ボタンUIが必要な場合は別途Webフォーム（`input.html` 系）の用意が必要。

## 汚染防止（設計の肝）

- GDLは**ファイル添付のみ**、かつ **Aの生成が終わってから**添付させる。
- 開始時に添付されてよいのは**質問プールと採点エンジンの2つだけ**。GDLらしきJSONが先に入ったら汚染としてやり直す。
- **A→B→C の順**を厳守（Cを先に見るとBがカンニングになる）。
- 選択肢の軸座標 `axis_pos` は被験者に一切見せない（見えると狙って答えられてしまう）。

## 中断復帰

コード実行環境のセッションは長時間の対話でリセットされ、変数が消えることがある。対策として **A確定時・B確定時・C収集10問ごと**に `ptt_state.json` を書き出す。落ちた場合は新しい会話でプロンプトを貼り直し、質問プール・採点エンジンとあわせて `ptt_state.json` を添付して「再開」と伝えれば続きから再開できる。

`ptt_state.json` には**質問IDのみ**を保存し、質問本体と `axis_pos` は含めない（被験者が開いても答えが漏れないため）。採点時はIDでプールから引き直す。

## 既知の限界（v1）

- 1回実施（A/B/C各1回）。揺らぎ低減には複数回平均が有効。
- 天井を1.0で近似（本来は人間のtest-retest自己一致）。Fidelityはやや低めに出る安全側。
- 軸B（人間かAIか＝ブレードランナー型）は未対応。v2で自由記述＋判定を追加予定。
- 選択式のみ。実際の文体は測っていない。
- 床(A)は実行環境とモデルに依存する。**異なるAIサービス・異なる時期の結果を直接比較しない**こと。

## ローカル検証（手元のPythonでも実行可）

```bash
# 出題サブセット作成（--n は 1=40問 / 2=80問）
python eval/ptt/ptt_scorer.py sample --pool eval/GDL_eval_pool.json --n 1 --seed 1234 --out subset.json --show

# A/B/C（各 {"answers":{"P0001":"A",...}} 形式）を用意して採点
python eval/ptt/ptt_scorer.py score --subset subset.json --a A.json --b B.json --c C.json \
       --subject mayo --model gpt --date 2026-08-17 --out-json result.json --out-md report.md
```
