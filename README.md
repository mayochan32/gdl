## 概要

**GDL（Ghost Description Language）** は、人間の個性・思想・行動パターン・価値観などを JSON 形式で構造化記述するための仕様です。

「攻殻機動隊」の「ゴースト」概念からインスピレーションを得ており、**その人らしさ（= ゴースト）をデータとして定義・保存・伝達**することを目的としています。

AIがGDLデータを読み込むことで、その人の個性を反映した応答・創作・意思決定が可能になります。

---

## 主な用途

- **AIパーソナライズ** — LLMにGDLを読み込ませて"その人らしい"AIを作る
- **デジタルツイン** — メタバース内でのアバターの個性定義
- **自己理解・記録** — 自分の価値観・思想を整理して残す
- **没後継承** — 本人の思想・個性をAIが継続的に語り継ぐ

## スキーマ構成

GDLは12のセクションで構成され、Lv3（最大詳細度）では **642項目以上** で人の個性を記述します。

| `identity` | 名前・職業・社会的アイデンティティ・デジタル存在 | 12 | 20 | 21 | 53 |
| `appearance` | 身体的特徴・ファッション・身だしなみ・身体との関係 | 26 | 36 | 20 | 82 |
| `background` | 学歴・職歴・転換点・健康歴・人生の物語 | 20 | 41 | 24 | 85 |
| `philosophy` | 世界観・価値観・倫理観・信念・思想的葛藤 | 20 | 21 | 24 | 65 |
| `personality` | 性格特性・行動パターン・深層心理・内的矛盾 | 27 | 42 | 29 | 98 |
| `knowledge` | 専門領域・学習スタイル・知的ルーツ・知の哲学 | 14 | 23 | 22 | 59 |
| `preferences` | 嗜好・ルーティン・消費スタイル・好みの根源 | 22 | 30 | 17 | 69 |

## 詳細度レベル — Lv1 / Lv2 / Lv3 の考え方

GDLは3段階の詳細度で個性を記述します。上位レベルは下位レベルを包含します。

| レベル | 観点 | AIが再現できること |
|---|---|---|
| **Lv1** | **Who** — 誰か（属性・表層のらしさ） | 話し方・口調・基本的な好みを再現 |
| **Lv2** | **How** — どう考え・動くか（思考プロセス・判断基準） | 判断・推論パターン、価値観に基づく行動を予測 |
| **Lv3** | **Why** — なぜそうなのか（深層心理・形成史・内的矛盾） | 人生の文脈・矛盾・葛藤を含めた深い人格再現 |

### 設計思想

レベルの区分は **「AIがどこまで再現できるか」** を軸にしています。

**Lv1（Who）** は「この人はどんな人か」を伝える表層情報です。名前、職業、話し方、好きなもの——初対面の人に自己紹介するレベルの情報が並びます。AIはこのレベルだけで口調や好みを再現できますが、「なぜその口調なのか」は知りません。

**Lv2（How）** は「この人はどう判断し、どう行動するか」のパターン情報です。意思決定スタイル、コミュニケーション戦略、日常のルーティン、対人関係の実践パターンなど、**行動の法則性**を記述します。AIはこのレベルで「この人ならこう判断するだろう」という予測が可能になります。

**Lv3（Why）** は「なぜこの人はそうなのか」の根源情報です。幼少期の環境、人格形成に影響した人物、思想の変遷、内面の矛盾や葛藤、無意識のパターン——**その人を構成した物語**そのものです。AIはこのレベルで表面的な再現を超え、矛盾を含んだ深い人格として振る舞えるようになります。

### レベル間の関係

```
Lv1: 「私はコーヒーが好きです」
Lv2: 「朝に必ず1杯。豆はシングルオリジンを選ぶ」
Lv3: 「父が毎朝淹れていたコーヒーの香りが原体験。安心と探求の象徴」
```

Lv1だけでもAIは「コーヒー好きな人」として振る舞えます。Lv2があれば行動パターンを再現でき、Lv3があれば「なぜコーヒーにこだわるのか」という物語まで含めた応答が可能になります。

### Lv3の情報はAIの行動推論に使えるか？

使えます。LLMはLv3の形成史情報から暗黙の行動ルールを推論できます。例えば「攻殻機動隊の台詞に影響を受けた」という形成史があれば、明示的なルールがなくても「SF的な比喩を好む」と推論して応答トーンを調整できます。Lv2が「切り替えのルール」、Lv3が「切り替えの文脈と深み」として機能する関係です。

## マスター + ジェネレーター構成

GDLスキーマはマスターファイル（`GDL_schema_v1.json`）を単一の信頼できる情報源（Single Source of Truth）として管理し、ビルドスクリプトでレベル別ファイルを自動生成します。

```
GDL_schema_v1.json （マスター）
    │
    ├── build_schemas.js で自動生成 ──┐
    │                                  │
    ├── GDL_schema_lv1.json  ←────────┤  Lv1 項目のみ
    ├── GDL_schema_lv2.json  ←────────┤  Lv1 + Lv2 項目
    └── GDL_schema_lv3.json  ←────────┘  Lv1 + Lv2 + Lv3 項目（全項目）
```

レベル別ファイルは `node build_schemas.js` で再生成できます。

## _labels マップ

GDLデータ本体は英語キーで統一されており、`_labels` セクションに日本語対訳マップが記述されています。

```json
{
  "_labels": {
    "identity.name": "名前",
    "philosophy.core_values": "核となる価値観",
    ...
  },
  "gdl": {
    "meta": { ... },
    "identity": { ... }
  }
}
```

データをクリーンに保ちつつ、多言語環境でも意味を参照できる設計です。

## 入力フォーム

`input.html` をブラウザで開くと、インタビュー形式の質問にラジオボタン・チェックボックス・スライダーで回答でき、GDL JSONを自動生成・ダウンロードできます。

- テキスト入力は名前・生年のみ
- すべての性格・価値観項目は選択式
- 回答完了後に `GDL_（名前）_（日付）.json` としてダウンロード

※ 入力フォームは現在Lv1対応です。Lv2/Lv3対応は今後のアップデートで予定しています。

## AIへの読み込み方

### OpenAI GPTs

1. GPTsの「Instructions」にシステムプロンプトを設定
2. 「Knowledge」にGDLファイル（.json）をアップロード
3. 「あなたらしく答えてください」でGDLを参照した応答が得られる

### Claude（Anthropic）

1. プロジェクトの「Project Knowledge」にGDLファイルをアップロード
2. システムプロンプトでGDLに基づく応答を指示
3. GDLを参照した個性再現が可能

### その他のLLM

GDLはJSON形式のため、システムプロンプトやコンテキストウィンドウに読み込めるLLMであれば利用可能です。
